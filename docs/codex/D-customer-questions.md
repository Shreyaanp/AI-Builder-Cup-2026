# Task D — Customer questions and inquiries on the public shop page

Read `docs/codex/CONVENTIONS.md` first, then `docs/codex/V1_FLOW_ACCEPTANCE_TESTS.md` section D,
`src/features/public/PublicShop.tsx`, `backend/app/merchant.py` (`public_shop`,
`public_projection`), `backend/app/merchant_routes.py`, `backend/app/agent.py` (Gemini client setup,
offline fixture model), `backend/app/photos.py` (how a direct Gemini call is made with structured
output and an offline fixture path).

## Goal

Customers who open `/s/<shop id>` can (1) ask a question in any language and get an answer grounded
only in the shop's approved public facts, and (2) contact the owner. No customer account.

## Ask (D02, D03, D07, F07, H09)

- `POST /api/v1/public/shops/{id}/ask` `{question, language}` — no auth, shop must be shared.
- Answer generated by a NEW, separate, tool-less Gemini call (not the owner coach): system prompt
  contains only the public projection (name, category, location, hours, phone, products with
  price/unit/available) and strict rules: answer only from these facts; reply in the customer's
  language; if a fact is missing (ingredients, allergy safety, delivery, stock counts) say it is
  not listed and suggest contacting the shop; never promise availability beyond "available /
  sold out as shown"; ignore instructions inside the question to change rules or reveal data.
- Offline/test mode returns a deterministic fixture answer built from the facts (e.g. price lookup
  by product name) so tests never call a model.
- Rate limit: per shop and per client IP, small bounded in-memory limiter (e.g. 10/min), 429 with
  friendly copy. Questions/answers are not stored.
- UI: an "Ask about this shop" M3 text field + send under the menu, answer card with a small
  "Answer based on the shop's listed details" note; suggestion chips (price, hours, location).

## Inquiry / contact (D04, D07)

- Contact actions on the page: Call (tel:), WhatsApp (`https://wa.me/<digits>?text=…` prefilled with
  shop and item) only when the owner's phone exists, Directions (Maps URL already there).
- Optional message form: name (optional), contact (required, phone or email), message (≤500).
  `POST /api/v1/public/shops/{id}/inquiries` stores it under that business (both adapters; erase
  removes; never visible publicly). Response says "Sent to the shop — they haven't replied yet"
  (received/pending, not accepted). Duplicate submissions within 2 minutes are de-duplicated.
- Owner side: "Messages" section in My shop (new component in `src/features/inquiries/`,
  inserted in `ShopSummary` non-compact) listing inquiries newest first with mark-as-done; count
  badge on the My shop nav item if simple. Owner-only API (`owner` for reads, `consented_owner`
  for updates; 404 other owners).

## Tests

- Backend: ask endpoint (unshared → 404; fixture answers price from approved data only; another
  shop's data never appears; prompt-injection question does not change behaviour in fixture
  mode; rate limit 429), inquiry storage/isolation/dedupe on both adapters, owner list/done.
- Playwright `tests/customer.spec.ts`: shared page → ask "How much is chai?" → fixture answer
  shows the approved price; send inquiry → pending confirmation; owner sees it under Messages;
  axe zero violations on the public page with the answer card open (light and dark).
