# FORECAST implementation evidence

Local work only. No commit, push, deployment, live model call, cloud resource change, billing change, or IAM change. The task's final no-commit instruction and CONVENTIONS.md were followed.

| Requested build        | Implementation and evidence                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1. Universal ingestion | The existing owner-scoped, rate-limited import endpoint accepts CSV/XLSX, JPEG/PNG/WebP, PDF, and UTF-8 pasted notes. Gemini extraction uses the existing client configuration and a structured schema. Images pass existing sanitization and moderation before extraction, with no image storage in this import path. Cleaning normalizes dates, matches saved product aliases, merges case/spacing variants, removes totals/subtotals, and returns review flags. Incomplete sales and truncated extraction are rejected. Menu and sales data still require the exact sealed digest to save.                           |
| 2. Bulk coach products | The existing coach photo endpoint prepares all priced items through one `propose_products` call. Product proposal/photo caps are aligned at 200. Saved availability is preserved. The prompt explicitly requests a single bulk proposal; a synthetic menu-image eval case was added. A mocked 40-item photo regression passes. The live Gemini eval was not executed.                                                                                                                                                                                                                                                   |
| 3. Forecast            | An owned GET forecast endpoint and coach tool return seven days per eligible item. Default fallback uses weekday seasonality and a bounded recent-level trend. Explicit `forecast_backend=bigquery` uses parameterized inline data with `AI.FORECAST`, project `ichiropractic`, default dataset `chalkboard_analytics`, and `asia-south1`. Responses label the actual method and include available intervals. Failed/incomplete provider output falls back with an explicit reason. The My shop Prep plan tile shows tomorrow's top three items and method; its coach question works through the offline ADK tool path. |
| 4. Upload entry points | The import label names Excel, photo, and notes. Phones offer a separate rear-camera capture input alongside file upload. Pasted notes have a multiline field and review action. New copy is present in English and all nine translated dictionaries. Offline AI extraction has a clear recovery message.                                                                                                                                                                                                                                                                                                                |

Forecast eligibility is conservative: at least 28 recorded dates per item and a latest observation within seven days. Missing dates are unknown, never invented zero-sales days. Ambiguous numeric dates use day-first interpretation and receive a review flag. Owners see the exact cleaned daily rows before confirming; saving retains the existing explicit replacement semantics for those dates.

## Open risks

- The full frontend check remains blocked by the classic phone sign-in test; the separate worker owns the relevant UI scope. Whole-repo formatting also has the untouched handoff-document warning.
- Actual OCR accuracy, live multimodal coach tool choice, BigQuery SQL/provider output, TimesFM availability in `asia-south1`, and IAM access were not validated against external services. No dataset was created. Provider failures return the labelled deterministic fallback.
- Sparse/closed-day histories may require more than four calendar weeks to reach the 28-recorded-day threshold. The fallback does not claim prediction intervals; TimesFM returns them when available.
- Automated phone emulation and axe scans do not establish physical camera behavior or native-language translation quality.
