## Story gaps

### S1 — Owner setup

Consent, text/photo proposal approval, cancellation, readiness entry, structured opening/closing hours, custom payment/delivery names, separately approved EXIF GPS, sharing and QR are exercised locally. Photo output is an explicitly labelled fixture. Real camera orientation/large-photo handling, GPS accuracy, real recognition and hosted Google sign-in are unvalidated here. Q7 weakens validation recovery. Existing template/project-memory references use older branding and statuses; this report treats the checked-out implementation as evidence.

### S2 — Daily upkeep

The combined INR price/sold-out instruction is reviewed before saving; public polling propagates availability across separate contexts. Inline-price validation/cancel/save, CSV approval and daily-data persistence are tested. The 28-day CSV saves exactly 840 units and 1,512,000 INR minor units (₹15,120). Q6 makes Close the day retries unsafe. Photo/PDF/Excel recognition correctness and real voice recognition are not established by offline fixtures. “Updates instantly” should be described as bounded polling rather than zero-delay delivery. Full pending-action/conflict UX after every stale edit remains outside this suite.

### S3 — Customer discovery and owner conversation

Anonymous facts, truthful halal limitations, currency, public/private projection, sharing withdrawal, authenticated message/reply, reload, server-failure retry and owner-close propagation are covered. Q8 bypasses the intended identity policy; Q10 duplicates same-shop conversations under a coordinated race. Q11 creates substantial desktop chat overflow. Nearby discovery uses local fixtures; it does not establish real Maps/GPS coverage. Browse and AI discovery must preserve clear demo labels. Bengaluru selection, map/list switching and the known-halal filter survive reload. A full nearest-first, category/budget/open-now matrix in eight populated cities is still needed.

### S4 — Forecast → Source → Sell

Approved 28-day sales activate the weekday forecast. Empty-history and planning-outage states preserve input. Supplier cards and automatic replies must retain demo/no-payment labels; Orders must persist. Q12 blocks the phone touch flow; Q13 breaks populated Orders list semantics. Q14 adds a small desktop Tamil sheet overflow. The desktop keyboard route completes the order flow; the phone touch route stops at its Q12 expected failure. A separate locally arranged order exposes Q13 on the phone too. Deliveries of raw ingredients do not automatically prove that a finished menu item is sellable: flour → recipe yield → finished-stock → customer availability still needs an explicit business rule and acceptance journey. Forecast uncertainty/units and real supplier acceptance require separate evidence.

### S5 — Google

Details, gallery upload/error, INR preview, persistence and the explicit “Waiting for Google API access” state are exercised. Official links are inspected without opening them. Sign-in, merchant authority, verification and publication remain separate; this local suite does not establish any Google publication right or successful publishing. Removal/limit/malicious-media matrices are primarily covered by existing backend tests, not exhaustively repeated through this UI suite.

### S6 — Identity and privacy

Consent, owner/customer isolation, destructive confirmation/cancel and removal of owner/public data are covered. Q5 hides preference-deletion failure; Q9 leaves copied business data behind. Customer profile offers preference clearing rather than a complete customer-account erasure journey; retention and deletion of chats, tips, follows and identity need a clear customer policy. Physical face/liveness and camera checks are deferred; they must remain optional and separate from business authority.

### S7 — Language and country

The language picker exposes all 15 supported languages. Tamil is exercised in every area, INR is checked through review/public/Google paths, and text scaling is sampled at 125%. Q1 and Q2 prevent a complete Tamil journey. Picking a language does not prove multilingual ASR/TTS, translation quality or all plural/date/number variants. All 15 full workflows, zero-/three-decimal currencies and cross-timezone day boundaries need broader UI coverage; existing backend money/hours tests provide narrower automated evidence.

### Customer community

Follow/unfollow, local reload persistence, merge into local signed-in identity, Saved/Chats empty states, moderated tips, literal HTML-like text, owner-visible tips, deletion and preference-failure handling are covered. Q2–Q5 leave localization and recovery gaps. Device stamps are explicitly device-only and are checked against repeated same-day visits. A device-only staff-reset card is not merchant-authorized fraud prevention or cross-device loyalty accounting. Customer-account deletion, moderation appeals/reporting, live safety checks, actual Google profile synchronization and durable demo replies across server restarts remain gaps or unvalidated work.

## Reproduction and verification

Install dependencies from an existing offline cache. The fresh worktree's locked Python install could not find a cached NumPy wheel; this run used an already-installed local Python environment without syncing or changing lockfiles.

```powershell
# Use a local installed Python environment containing the locked dependencies.
$env:QA_PYTHON = '<local-python.exe>'
$env:WEB_PORT = '3437'
$env:API_PORT = '3537'
npx playwright test -c tests/qa/playwright.config.ts
```

In this Windows sandbox Playwright-managed server teardown hung. The completed verification instead starts `node tests/qa/server.mjs` and `npm run dev` in separate local terminals, then runs:

```powershell
$env:QA_EXTERNAL_SERVER = 'true'
npx playwright test -c tests/qa/playwright.config.ts
```

Run backend tests before browser tests: pytest's generated HTML fixtures can trigger Vite reloads when both run concurrently under this worktree. Backend verification uses `uv run --locked --no-sync pytest -q --basetemp=.cache/pytest-qa-final --tb=short` with `UV_OFFLINE=true`, `UV_NO_CACHE=true` and `UV_PROJECT_ENVIRONMENT` pointing to that installed environment. The worktree-local temp directory avoids sandbox denial of pytest's default Windows temp folder.

The final browser run contains **59 cases × 2 projects = 118 executions: 92 passed, 26 expected failures, zero unexpected failures, zero skips and zero retries** (4.9 minutes). Playwright's aggregate “118 passed” includes matching expected failures. See [results.json](results.json) for individual assertions, axe output and layout measurements.

Backend: **516 passed, 94 skipped, 3 strict expected failures** in the complete offline run; the three new regressions were also rerun independently. See [backend-results.txt](backend-results.txt) and [backend-regressions.txt](backend-regressions.txt).

Q14 is intermittent. Its tests always assert the width invariant; they mark the known defect as an expected failure only when the extra width actually reproduces. A fitting layout is a normal pass, so future pass/expected-fail counts can differ without implying the defect was fixed. The 19 screenshots are at most 390×844; Q3 is a smaller region capture, and Q11/Q14 are explicitly labelled desktop crops.

Checks: `npx tsc -b --noEmit`, scoped ESLint, Prettier, Ruff (check and format), and `mypy app` passed. Plain `npm run lint` was attempted but did not finish during the extended audit; the completed lint command is `npm run lint -- --ignore-pattern '.cache/**' --ignore-pattern 'backend/.cache/**' --ignore-pattern 'graphify-out/**'`. These exclusions cover generated artifacts, not application/test source. Cache cleanup was blocked by the environment and no product lint configuration was changed.

One extended run lost the local preview backend without a captured traceback; the complete matrix above was rerun against a fresh preview process. The cause of that earlier exit is unconfirmed, and soak stability is not established. This audit does not include Lighthouse, hosted header verification or an online dependency-advisory lookup.

Changed files: 13 area specs plus QA support/config/server under `tests/qa/`; three backend regressions in `backend/tests/test_qa_regressions.py`; this report, result logs and screenshots under `docs/qa/`. The knowledge graph was refreshed with AST-only `graphify update .`. Existing story reports, product source and lockfiles were not changed.

Material/web review: component semantics **0/2** (Q13), feedback states **0/2** (Q3–Q6), accessibility **0/2** (Q7/Q11/Q12), adaptive behavior **1/2** (phone works in sampled flows; desktop overflow remains). Typography/spacing/semantic labels were sampled in English and Tamil; this is not approval of every token or screen.

Product files were not changed. No commit or publication was performed.
