# oGoogle AI working rules

Current scope: complete deployment of the Python/FastAPI/Google ADK and React template, using one Cloud Run service, Firebase Google sign-in, and persistent cloud conversations. Reuse `ichiropractic` with separate app resources and a dedicated Firestore namespace. Product naming is independent and does not imply Google affiliation. The older POC is outside this repository's evidence.

Initial public source is verified on `main` at commit `c79cd7f`; subsequent run `38439971679` passed. The updated release workflow and hosted URL still need remote verification. Live provider use and submission readiness remain separate statuses.

- Information maintenance and business coaching; no marketplace, automatic public listing or inferred ownership.
- Default to explicit offline fixtures. An installed SDK or adapter is not live inference, speech recognition, native Google placement or publishing access.
- Keep model keys, OAuth tokens and signing secrets server-side, out of Git, logs and project memory. Firebase browser configuration is public by design; use a dedicated referrer/API-restricted key, never a Gemini key. Local conversation files and signing keys are ignored private data.
- Agent tools read and propose only. Any future business write requires server-verified business authority, exact approval, validation and an idempotent audit receipt.
- Use semantic Material tokens and official React/Python guidance. Preserve keyboard access, text scaling, reduced motion and truthful states.
- Test real streaming disconnect/cleanup, owned sessions, input limits and incomplete responses. Automated browser emulation does not prove phone installation, microphone accuracy or full accessibility.
- Prefer free resources; do not enable billing or deploy without authorization. Existing agreed ₹500 total GCP cash ceiling is not an enforced cap or renewable per-service allowance. Budget setup remains paused.
- Latest deployment choices authorize this release and supersede the earlier local-review/push-only scope. Checks run on push/PR; cloud releases require manual workflow dispatch of a checked main commit. Default model remains offline. Google sign-in establishes account identity, not business ownership.

Competition: Retail & Commerce. Final Google-model use, qualifying Google Cloud deployment, public source, demo and deck still require separate validation. This local fixture is not a compliant final submission. Original source references: [FAQ](https://aibuildercup.com/Faqs.html), [themes](https://aibuildercup.com/themes.html). The workspace-level rules retain the broader researched requirements.
